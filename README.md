# NoScribe — AI-Powered Meeting Assistant

NoScribe turns a recorded English-language meeting into an accurate transcript and a trustworthy written record. A three-model pipeline transcribes the audio, repairs domain-specific terminology, and then produces structured minutes, key decisions and action items. Nothing is hardcoded: every output is generated by the pipeline from the uploaded audio.

---

## 1. Pipeline at a glance

```
 audio upload ──► validation & decode (16 kHz mono)
                        │
        ┌───────────────▼────────────────┐
        │ Stage 1  Speech-to-text         │  Whisper large-v3-turbo (Groq, hosted)
        │          + speaker diarization  │  fallback: faster-whisper large-v3-turbo (local)
        └───────────────┬────────────────┘
                        │  raw transcript (kept)
        ┌───────────────▼────────────────┐
        │ Stage 2  Domain-aware refinement│  LLM #1: openai/gpt-oss-20b
        │          + safety guards        │
        └───────────────┬────────────────┘
                        │  refined transcript (kept)
        ┌───────────────▼────────────────┐
        │ Stage 3  Minutes / decisions /  │  LLM #2: openai/gpt-oss-120b
        │          action items           │  + grounding verification
        └───────────────┬────────────────┘
                        ▼
      Gradio UI  ·  .txt / .md / .json downloads
```

### Models and their roles

| Stage | Role                                   | Model                             | Notes                                                                                                   |
| ----- | -------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1     | Speech-to-text                         | `whisper-large-v3-turbo` via Groq | Local `faster-whisper` (`large-v3-turbo`, int8) used automatically if Groq fails or `STT_BACKEND=local` |
| 2     | Transcript refinement (**LLM #1**)     | `openai/gpt-oss-20b`              | Corrects mis-recognised technical terms/acronyms only                                                   |
| 3     | Minutes, decisions, tasks (**LLM #2**) | `openai/gpt-oss-120b`             | Larger model for reasoning and structured extraction                                                    |

The two language-model roles are separate stages with separate prompts and separate models. Prompts live in the notebook as `REFINER_PROMPT` (Cell 5) and `MINUTES_PROMPT` (Cell 6).

## 2. Features

- **One-click end-to-end run**: upload → transcribe → refine → document → download.
- **Raw and refined transcripts kept side by side**, plus a **corrections table** (heard vs corrected, with timestamps).
- **Speaker identification** ("Speaker 1…N"), optional renaming (`Speaker 1=Priya, Speaker 2=Alex`) applied without re-running any model.
- **Domain glossary** (built-in plus user-supplied extra terms) biases Whisper and guides the refiner.
- **Decisions vs. proposals**: only explicitly agreed items become decisions; suggestions go to _Proposals / Open Items_.
- **Owners and deadlines are never guessed**: shown as `unspecified` unless stated in the recording.
- **Evidence for every claim**: each decision/task carries a verbatim quote from the transcript.
- **Clear errors**: unsupported type, empty file, unreadable/corrupt audio, silence, <1 s clips, and no detected speech all produce a readable message in the status box.
- **Live status** for each stage and a final summary line (time taken, model used, corrections applied).

### Anti-hallucination safeguards

| Layer                                    | What it does                                                                                                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Refinement guard (`guard_ok`)            | Rejects an LLM rewrite if numbers or negations changed, if length changes by more than ±25–35%, or if text similarity drops below 0.6; the raw text is kept instead |
| Strict ids                               | Refiner must return the same turn ids in the same order; missing turns fall back to raw text                                                                        |
| Evidence grounding (`verify_extraction`) | Drops any decision/proposal/task whose quote cannot be found in the transcript                                                                                      |
| Owner / deadline check                   | Resets to `unspecified` if the name or time phrase does not appear in the transcript                                                                                |
| Temperature 0, JSON mode                 | Deterministic, parseable outputs; automatic retries with backoff                                                                                                    |

## 4. Setup

### Prerequisites

- Python 3.10+
- A free [Groq API key](https://console.groq.com/keys)
- Internet access (for Groq). Local fallback STT works offline after the first model download.

### Install

```bash
git clone <your-repo-url>
cd <your-repo>
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Configure

The API key is **never stored in the notebook**. Provide it in either way:

```bash
export GROQ_API_KEY="gsk_..."      # Windows PowerShell: $env:GROQ_API_KEY="gsk_..."
```

or paste it when the notebook prompts for it.

Optional environment variables:

| Variable         | Default                  | Meaning                                                 |
| ---------------- | ------------------------ | ------------------------------------------------------- |
| `STT_BACKEND`    | `auto`                   | `auto` (Groq first, local fallback), `groq`, or `local` |
| `GROQ_STT_MODEL` | `whisper-large-v3-turbo` | Hosted STT model                                        |
| `STT_MODEL_SIZE` | `large-v3-turbo`         | Local faster-whisper model size                         |
| `LLM_REFINER`    | `openai/gpt-oss-20b`     | LLM #1 (refinement)                                     |
| `LLM_MINUTES`    | `openai/gpt-oss-120b`    | LLM #2 (minutes/decisions/tasks)                        |
| `HF_TOKEN`       | unset                    | Enables optional pyannote diarization                   |

## 5. Run

### Option A — Jupyter locally

```bash
jupyter notebook main_improved_1.ipynb
```

Run all cells in order. The last cell launches the Gradio interface inline.

### Option B — Google Colab / Kaggle

Upload the notebook, run **Cell 1** (installs dependencies), then run the remaining cells. Add `GROQ_API_KEY` as a secret or paste it when prompted.

### Using the interface

1. Upload a meeting recording (`.mp3 .wav .m4a .flac .ogg .aac .wma .mp4 .webm .opus`).
2. _(Optional)_ set the number of speakers (0 = auto), extra domain terms, and speaker names.
3. Click **Process Recording** and watch the stage-by-stage status.
4. Inspect the tabs: **Raw transcript → Refined transcript → Corrections → Meeting record**.
5. Download from the file panel.

## 6. Outputs

| Output                               | File                     | Format           |
| ------------------------------------ | ------------------------ | ---------------- |
| Raw transcript                       | `raw_transcript.txt`     | Human-readable   |
| Refined transcript                   | `refined_transcript.txt` | Human-readable   |
| Minutes, key decisions, action items | `meeting_record.md`      | Human-readable   |
| Complete structured record           | `meeting_record.json`    | Machine-readable |

The Markdown and JSON records are generated from the same data object, so they contain identical decisions and tasks.

## 7. Mapping to the problem statement

| Requirement                                                 | Where it is met                      |
| ----------------------------------------------------------- | ------------------------------------ |
| Accept English meeting audio, one run from upload to output | Gradio UI + `run_pipeline`           |
| Speech-to-text raw transcript visible                       | Tab 1                                |
| Domain-aware refinement by an LLM, shown separately         | Stage 2, Tab 2, Corrections tab      |
| Separate LLM for minutes, decisions, tasks                  | Stage 3 (`gpt-oss-120b`)             |
| Preserve names, numbers, negation, commitments              | Refiner prompt + `guard_ok`          |
| No invented owners/deadlines; proposals ≠ decisions         | Minutes prompt + `verify_extraction` |
| Clear errors for bad files                                  | `load_audio` validation              |
| Human- and machine-readable record, same content            | `.md` and `.json`                    |
| Status display                                              | Live status box                      |
| Nothing hardcoded                                           | All outputs produced at run time     |

## 8. Limitations

- Requires a Groq account and network for the default models (local STT fallback exists, but the LLM stages need the API).
- Lightweight diarization (MFCC + pitch clustering) is less accurate than pyannote; overlapping speech is not handled.
- Heavily accented speech, noisy rooms and very rare jargon can still cause recognition errors; add terms in the _Extra domain terms_ box.
- Groq free-tier rate limits may slow very long meetings (the pipeline retries with backoff).
